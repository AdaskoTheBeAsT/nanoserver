# Compatibility & Runtime Hardening Plan (2026-11-14)

## Review update (2026-11-15)

Reviewed against the application's `docs/` and `.factory/skills/`, the current
shim/installer, and `docs/roundtable-fix-validation.md`. The items below amend
the original design; they are acceptance requirements, not completion claims.

- Work only on local candidate images. Do not publish, replace `-v1.7.0` tags,
  or run the installer against workstation system files or registry keys.
- NS-01 must verify the real Windows export names **and ordinals** on both
  architectures. Property-frame UI must return an honest unsupported result,
  never fabricated success. Install and preflight every new payload, and
  synchronize its hashes into all six build contexts.
- NS-02 must reject negative counts and overflowing widths without reading an
  unbounded NUL-terminated string. Test empty text, optional outputs, exact-fit
  boundaries and guard bytes. Fixed headless metrics are not real font shaping.
- NS-03 must cover ordinary imports, dynamic lookup, modules loaded after
  startup, and calls from `DllMain`. A loader notification occurs before import
  binding is necessarily complete, so a notification-only IAT write is **not**
  proof of pre-`DllMain` interception. Do not change kernel32 KnownDLL settings.
  Exercise integer atoms, case-insensitive names, reference counts, exhaustion,
  concurrent callers, disable/restore, and preservation of OS-owned atoms.
- NS-04 must retain existing image users (including IIS service identities),
  use SID-based ACLs, and test canonicalization as `ContainerUser`, not merely
  from the administrator build layer. No machine-wide `setx` is necessary when
  Docker `ENV` already supplies the process environment.
- NS-05 must balance **every successful** COM/OLE initialization, preserve
  `RPC_E_CHANGED_MODE`, propagate persistence errors and short reads/writes,
  and implement advise enumeration, `ADVF_PRIMEFIRST`, `ADVF_ONLYONCE`,
  `ADVF_NODATA`, ownership, and reentrant callback safety. Resolve original
  APIs before replacing imports to prevent recursion.
- NS-06 additionally requires **classic shlwapi ordinal compatibility**.
  Legacy MSXML imports Unicode kernel32/user32 wrappers by ordinal; adding
  `StrCpyW`/`StrCatW` names alone cannot remove those application IAT patches.
  Verify the ordinal-to-function ABI against a Windows control and preserve
  unrelated existing exports. `StrCpyNW` and `StrNCatW` have different count
  semantics and need separate boundary tests.
- NS-07 must not invent a successful general-purpose activation context or
  claim CRT support from export presence alone. Trace the actual VC80/VC90
  queries and qualify an unmodified CRT plus its private manifest. Keep
  unsupported paths explicit until that real loading test passes.
- NS-08 must implement the native dispenser interfaces with correct driver
  ownership, resource allocation/destruction, repeated close, and unload
  behavior. Add `DispManGetContext` as required by real callers. No managed
  callback or executable writable allocation may be needed during teardown.
- **NS-09 (P1), capability and regression contract:** expose a versioned,
  additive native capability query so managed libraries can select one provider
  before starting STA threads. Run ordinary-import controls and a late-loaded
  fixture, native COM persistence/advise/dispenser tests, installer rollback
  tests, and existing provider-switching isolation tests. Never infer a
  capability solely from an image tag or an exported but nonfunctional stub.

Application-specific numeric scratch resets, malformed vendor SAFEARRAY
producers, Fortran file-sharing tables, license policies and native TLS-template
offsets remain application responsibilities. Do not move their binary offsets
or vendor names into this generic base image.

## Executive summary

Production qualification of 30+ legacy 32-bit x86 and 64-bit native/COM calculation engines on `adaskothebeast/nanoserver:aspnet-x86-10.0.14-ltsc2025-v1.7.0` confirmed that the `1.7.0` OS-level STA, window/message-queue, CBT/dialog, and headless GDI shims work reliably, while exposing **seven concrete OS-layer compatibility gaps** that currently force downstream applications to maintain per-module PE binary patchers or runtime IAT hooks:

1. **Missing `olepro32.dll` forwarder DLL** in `SysWOW64` (`ERROR_MOD_NOT_FOUND = 126` for Delphi 6/7 VCL/ActiveX COM servers importing `OleLoadPicture`, `OleCreateFontIndirect`, `OleCreatePictureIndirect`, `OleCreatePropertyFrame`).
2. **Missing `gdi32.dll!GetTextExtentExPointA` export** (`ERROR_PROC_NOT_FOUND = 127` for ANSI VCL `Graphics.TCanvas` and Unicode form wrappers). Note: `GetTextExtentExPointW` and all 15 Enhanced Metafile (`*EnhMetaFile*`) exports required by Fortran/GDI report generators are already present in `v1.7.0`.
3. **Win32 Global Atom Table `ERROR_ACCESS_DENIED (5)` under `ContainerUser`** (`kernel32!GlobalAddAtomA/W`, `GlobalFindAtomA/W`, `GlobalDeleteAtom`, `GlobalGetAtomNameA/W`), which aborts `DllMain(DLL_PROCESS_ATTACH)` in Delphi VCL `Controls.InitControls` when running as non-admin `ContainerUser`.
4. **Stubbed legacy OLE2 delay-load exports in `ole32.dll`** (`CoInitialize`, `OleInitialize`, `OleUninitialize`, `OleRun`, `OleSaveToStream`, `OleLoadFromStream`, `CreateDataAdviseHolder`, `OleLockRunning`), whose export names exist in `SysWOW64\ole32.dll` as `ext-ms-win-com-ole32-l1-*` delay-load stubs that fail at runtime unless intercepted.
5. **Unpromoted `shlwapi.dll` forwarder and missing `StrCpyW` / `StrCatW` exports** (`SysWOW64\shlwapi.dll` is absent outside `SysWOW64\forwarders`, and `forwarders\shlwapi.dll` omits `StrCpyW` and `StrCatW` imported by `msxml4.dll` and legacy ATL/OWL modules).
6. **`TEMP` / `TMP` default (`C:\Windows\TEMP`) breaks `GetLongPathNameA/W` under `ContainerUser`**, because `GetLongPathNameW` enumerates parent directory segments (`FindFirstFileW("C:\\Windows\\TEMP")`), causing Delphi `ComServ.ShortToLongFileName` (`ITypeLib` path canonicalization) and legacy C/C++ temp-file helpers to fail.
7. **Missing `comsvcs.dll` `CLSID_DispenserManager` (`{ECABB0C0-7F19-11D2-978E-0000F8757E2A}`)** required by MDAC / OLE DB (`oledb32.dll`, `msadce.dll`) and Jet 4.0 connection/resource pooling, plus `Shim_QueryActCtxW` compatibility with VC80/VC90 `msvcr80.dll` / `msvcr90.dll` `_check_manifest`.

## Detailed technical plan

### NS-01 (P0): Synthesize and install `olepro32.dll` in `SysWOW64`

#### Evidence
- `C:\Windows\SysWOW64\olepro32.dll` is absent on Windows Nano Server 2025 (`v1.7.0`), whereas `C:\Windows\SysWOW64\oleaut32.dll` is present.
- 32-bit Borland Delphi 6/7/2007 ActiveX and VCL libraries (`AxCtrls.pas`) statically link `olepro32.dll` (`OleCreateFontIndirect`, `OleCreatePictureIndirect`, `OleCreatePropertyFrame`, `OleCreatePropertyFrameIndirect`, `OleIconToCursor`, `OleLoadPicture`, `OleTranslateColor`), failing `LoadLibraryExW` with `ERROR_MOD_NOT_FOUND (126)`.
- On full Windows Desktop/Server Core, `SysWOW64\olepro32.dll` is purely an export-forwarder stub DLL forwarding to `oleaut32.dll` (plus `DllCanUnloadNow` / `DllGetClassObject` / `DllRegisterServer` / `DllUnregisterServer`).

#### Implementation
1. Add a minimal CRT-free 32-bit PE32 DLL target `olepro32.cpp` + `olepro32.def` in `sta-shim/build_shim.ps1` (matching `nanoserver_sta_shim_x86.dll` compiler/linker flags: `/GS- /Zl /NODEFAULTLIB /ENTRY:DllMain`, CFG metadata enabled).
2. Define exact ordinal and named exports in `olepro32.def` matching Windows `SysWOW64\olepro32.dll` (base ordinal `248`):
   ```def
   LIBRARY olepro32
   EXPORTS
       OleIconToCursor                = oleaut32.OleIconToCursor                @248
       OleCreatePropertyFrameIndirect = oleaut32.OleCreatePropertyFrameIndirect @249
       OleCreatePropertyFrame         = oleaut32.OleCreatePropertyFrame         @250
       OleLoadPicture                 = oleaut32.OleLoadPicture                 @251
       OleCreatePictureIndirect       = oleaut32.OleCreatePictureIndirect       @252
       OleCreateFontIndirect          = oleaut32.OleCreateFontIndirect          @253
       OleTranslateColor              = oleaut32.OleTranslateColor              @254
       DllCanUnloadNow                                                          @255 PRIVATE
       DllGetClassObject                                                        @256 PRIVATE
       DllRegisterServer                                                        @257 PRIVATE
       DllUnregisterServer                                                      @258 PRIVATE
   ```
   Where `oleaut32.dll` on Nano Server itself stubs any property-frame UI export, route `OleCreatePropertyFrame` / `OleCreatePropertyFrameIndirect` to `nanoserver_sta_shim` headless `E_NOTIMPL` / `S_OK` stubs so load-time import resolution always succeeds.
3. Add `L"olepro32.dll"` to `install_sta_shim.cpp` WoW64 installation and `VerifyPatchedPe` checks (`SysWOW64\olepro32.dll`).

#### Acceptance
- `LoadLibraryExW(L"olepro32.dll", nullptr, LOAD_LIBRARY_SEARCH_SYSTEM32)` succeeds in 32-bit processes on all five WoW64 flavours, and `GetProcAddress` resolves all 11 named/ordinal exports to valid executable addresses.

### NS-02 (P0): Add `gdi32!GetTextExtentExPointA` to `nanoserver_sta_shim` and `install_sta_shim`

#### Evidence
- `sta-shim/nanoserver_sta_shim.cpp` (`line 1799`) and `sta-shim/install_sta_shim.cpp` (`kGdi32Exports`, `line 657`) implement `GetTextExtentPoint32A` and `GetTextExtentPointA`, and `SysWOW64\gdi32.dll` already exports `GetTextExtentExPointW`, but `GetTextExtentExPointA` is missing (`ERROR_PROC_NOT_FOUND = 127`).
- Delphi VCL (`Graphics.TCanvas.TextExtent` / word-wrap helpers and ANSI/Unicode VCL form packages) statically imports `gdi32.dll!GetTextExtentExPointA`.

#### Implementation
1. Implement `Shim_GetTextExtentExPointA` in `sta-shim/nanoserver_sta_shim.cpp` using the existing deterministic 8x16 headless font cell metrics (`Shim_GetTextExtentPoint32A`):
   ```cpp
   extern "C" BOOL WINAPI Shim_GetTextExtentExPointA(
       HDC hdc, LPCSTR lpszStr, int cchString, int nMaxExtent,
       LPINT lpnFit, LPINT alpDx, LPSIZE lpSize) {
       (void)hdc;
       if (!lpSize) {
           SetLastError(ERROR_INVALID_PARAMETER);
           return FALSE;
       }
       if (cchString < 0) {
           cchString = lpszStr ? static_cast<int>(strlen(lpszStr)) : 0;
       }
       if (cchString > 0 && !lpszStr) {
           SetLastError(ERROR_INVALID_PARAMETER);
           return FALSE;
       }
       constexpr int kCharWidth = 8;
       constexpr int kCharHeight = 16;
       int fit = cchString;
       if (lpnFit) {
           fit = (nMaxExtent <= 0) ? 0 : (std::min)(cchString, nMaxExtent / kCharWidth);
           *lpnFit = fit;
       }
       if (alpDx) {
           int limit = lpnFit ? fit : cchString;
           for (int i = 0; i < limit; ++i) {
               alpDx[i] = (i + 1) * kCharWidth;
           }
       }
       lpSize->cx = cchString * kCharWidth;
       lpSize->cy = kCharHeight;
       return TRUE;
   }
   ```
2. Register `GetTextExtentExPointA=Shim_GetTextExtentExPointA` in `nanoserver_sta_shim.def`, `kExportTable` (`nanoserver_sta_shim.cpp`), and `kGdi32Exports` (`install_sta_shim.cpp`).

### NS-03 (P0): User-mode Global Atom Table fallback under `ContainerUser`

#### Evidence
- Under Nano Server's default `ContainerUser` account (which lacks an interactive window station), `kernel32!GlobalAddAtomA`, `GlobalAddAtomW`, `GlobalFindAtomA`, `GlobalFindAtomW`, `GlobalDeleteAtom`, `GlobalGetAtomNameA`, and `GlobalGetAtomNameW` invoke `NtUserAddAtom` / `NtUserFindExistingAtom` and fail with `0` (`LastError = ERROR_ACCESS_DENIED = 5`).

- Note on loader binding: `kernel32.dll` is a `KnownDLL` (`\KnownDlls\kernel32.dll` / `\KnownDlls32\kernel32.dll`), so patching `forwarders\kernel32.dll` alone will **not** intercept `kernel32.dll!GlobalAddAtomA` imports in loaded vendor DLLs.

#### Implementation
1. Implement an in-process thread-safe atom table (`0xC000..0xFFFF`, case-insensitive per Win32 atom semantics, supporting `#1234` integer atoms and reference counting) in `nanoserver_sta_shim.cpp`:
   - `Shim_GlobalAddAtomW` / `Shim_GlobalAddAtomA`
   - `Shim_GlobalFindAtomW` / `Shim_GlobalFindAtomA`
   - `Shim_GlobalDeleteAtom`
   - `Shim_GlobalGetAtomNameW` / `Shim_GlobalGetAtomNameA`
   Each wrapper first calls the OS `kernelbase`/`kernel32` implementation; if it succeeds, it returns the OS atom; if it returns `0` with `ERROR_ACCESS_DENIED` / `ERROR_INVALID_HANDLE` / `ERROR_CALL_NOT_IMPLEMENTED`, it delegates to the user-mode fallback table.
2. Hook `Global*Atom*` IAT thunks in newly loaded non-system modules inside `OnDllNotification` (`LDR_DLL_NOTIFICATION_REASON_LOADED`, which runs **before** the loaded module's `DllMain(DLL_PROCESS_ATTACH)` executes!) and during initial `RefreshHooksLocked()` module enumeration in `nanoserver_sta_shim.cpp`.
3. Restore original IAT thunks cleanly when `NanoServerStaShim_RestoreOriginal()` or `NANOSERVER_DISABLE_STA_SHIM=1` is active.

#### Acceptance
- Running as `ContainerUser` (`USER ContainerUser`), a test DLL that calls `GlobalAddAtomA`, `GlobalFindAtomA`, `GlobalGetAtomNameA`, and `GlobalDeleteAtom` inside `DllMain(DLL_PROCESS_ATTACH)` succeeds with non-zero `0xC000..0xFFFF` atoms and zero `ERROR_ACCESS_DENIED` failures.

### NS-05 (P1): Intercept `ext-ms-win-com-ole32-l1-*` in `nanoserver_sta_shim` for legacy OLE2 APIs

#### Evidence

#### Implementation

   - `Shim_OleRun(LPUNKNOWN pUnknown)`: queries `IID_IRunnableObject` (`{00000126-0000-0000-C000-000000000046}`); if implemented, invokes `IRunnableObject::Run(nullptr)`, otherwise returns `S_OK` per Win32 `OleRun` semantics.

   - `Shim_CreateDataAdviseHolder(LPDATAADVISEHOLDER* ppDAHolder)`: returns a lightweight COM-refcounted `IDataAdviseHolder` implementation supporting `Advise`, `Unadvise`, `EnumAdvise`, and `SendOnDataChange`.

#### Acceptance
